0. Qué vas a construir

Un sistema de seguridad completo que:

  1. Detecta movimiento con un sensor PIR y mide la luz ambiental con un LDR.
  2. Activa alarmas: LED rojo parpadeante, buzzer (sirena) y pantalla OLED con el estado.
  3. Se arma y desarma desde un botón físico o remotamente desde la nube.
  4. Publica telemetría y eventos por MQTT desde un ESP32 (simulado en Wokwi).
  5. Guarda todo en SQLite con fecha y hora: lecturas, eventos y comandos ejecutados.
  6. Muestra un dashboard en tiempo real en ThingSpeak y recibe comandos desde la nube.
   [Sensores PIR + LDR]
            |
            v  lectura cada 500 ms
   [ESP32 en Wokwi] ---- telemetría / eventos ----> [MQTT broker]
            ^                                          |
            |                                          v
     [comandos]  <----  [Backend Python]  ---->  [SQLite]
                                                      |
                                                      v
                                              [ThingSpeak nube]

4. PARTE B — Código del dispositivo (firmware)

B.1 Cargar los archivos

En el editor de Wokwi, junto a la pestaña main.py pulsa el botón + y crea los archivos config.py, sensors.py, actuators.py, display.py, net_mqtt.py y security.py, pegando el contenido correspondiente.

Wokwi copia todos los archivos del proyecto al sistema de archivos del ESP32, por lo que los import entre módulos funcionan igual que en Python normal.

B.2 Qué hace cada módulo

Archivo Responsabilidad Elementos clave
config.py Todo lo ajustable en un solo lugar pines, SSID, broker, tópicos, umbrales, temporizaciones
sensors.py Lee el hardware MotionSensor (PIR), LightSensor (LDR → lux)
actuators.py Controla salidas sin bloquear Led, Buzzer (PWM), AlarmPanel.tick()

B.3 El bucle principal (orientado a eventos, no bloqueante)

while True:
    now = time.ticks_ms()
    mqtt.check_messages()                     # 1. comandos desde la nube
    for payload in mqtt.drain_commands():
        system.handle_command(payload, "mqtt")
    ... botón local ...                       # 2. armado/desarmado físico
    if vencio SAMPLE_MS:                      # 3. lectura de sensores
        system.update(pir.read(), ldr.read_lux(), now)
    alarm_panel.tick(now)                     # 4. parpadeo y pitido
    if vencio TELEMETRY_MS:                   # 5. publicación
        mqtt.publish_telemetry(system.snapshot())
    if vencio DISPLAY_MS:                     # 6. pantalla
        display.render(system.snapshot())
    mqtt.ensure_connected()                   # 7. reconexión
    time.sleep_ms(50)

Nada de lo anterior espera la red: check_msg() retorna de inmediato si no hay mensajes, y los tiempos se comparan con time.ticks_ms().

B.4 Máquina de estados

  DESARMADO --(ARM/boton)--> ARMADO --(movimiento)--> ALARMA
       ^                       ^                        |
       |                       |                        |
       +---(DISARM/boton)------+<---(SILENCE/30 s)------+
       |                                            |
       +---------------(DISARM/boton)---------------+

Cada transición genera un evento (ARMED, MOTION_DETECTED, ALARM_ON, ALARM_SILENCED, ALARM_TIMEOUT, COMMAND_RECEIVED, …) que se publica por MQTT y se guarda en SQLite.

B.5 Comandos aceptados

Comando Acción
ARM / ARMAR activa la vigilancia (enciende LED verde)
DISARM / DESARMAR desactiva la vigilancia
SILENCE / SILENCIAR silencia la alarma manteniendo el sistema armado
STATUS / ESTADO reporta el estado actual
PING comprueba que el dispositivo responde

El parser acepta texto plano (ARM) o JSON ({"cmd":"ARM"}).

10. Defensa oral — preguntas frecuentes

¿Por qué MQTT y no HTTP? MQTT es un protocolo ligero publica/suscribe diseñado para IoT: poca cabecera, funciona con conexiones inestables, permite tópicos jerárquicos y que múltiples suscriptores reciban el mismo evento sin duplicar peticiones.

¿Por qué un broker público? Wokwi entrega conectividad real al ESP32, así que se puede usar broker.hivemq.com sin instalar nada. En producción se usaría un broker propio (Mosquitto/EMQX).

¿Qué significa "orientado a eventos"? La lógica no se ejecuta de forma lineal: los cambios (llegada de un comando, flanco del PIR, timeout de la alarma) generan eventos que se despachan a escritores interesados (emit() → MQTT → base de datos → dashboard).

¿Por qué el bucle es no bloqueante? Si se usara wait_msg() o sleep() largo, el ESP32 dejaría de leer sensores y de atender la alarma. Con check_msg() y comparación de ticks_ms() el sistema responde en menos de 100 ms.

¿Dónde corre SQLite y por qué? En el backend (PC), porque MicroPython en el ESP32 no incluye SQLite. El dispositivo sólo manda datos; la persistencia y las consultas se hacen en el lado servidor, que sí tiene ficheros y más recursos.

¿Cómo se sincronizan los tiempos? El firmware hace sync con un servidor NTP (ntptime) y publica el timestamp; el backend agrega recibido_at con la hora local, de modo que siempre hay fecha y hora en la base aunque el dispositivo no logre sincronizar.

¿Cómo llega un comando desde la nube hasta el ESP32? ThingSpeak TalkBack → REST (POST /talkbacks/<id>/commands/execute.json) → backend Python → publicación MQTT en seguridad/casa-01/command → callback del dispositivo → SecuritySystem.handle_command() → evento COMMAND_RECEIVED que vuelve al backend para marcar el comando como APLICADO.

¿Qué pasa si se cae la red o el broker? ensure_connected() reintenta cada 5 s con retroceso, el display muestra el error, y el sistema sigue funcionando localmente (lecturas, botón y alarma).

¿Cómo evitas los rebotes del botón? Debouncing por software: se registra el último instante de pulsación y sólo se acepta un nuevo flanco pasados BUTTON_DEBOUNCE_MS (250 ms).

¿Por qué dos LEDs y no uno? Para separar semántica: verde = sistema armado (vigilancia activa), rojo = alarma activa. Así se comprueba de un vistazo el estado sin mirar la pantalla.

¿Cómo mediste la iluminación en lux? Se convierte el valor del ADC a tensión, luego a resistencia del LDR con el divisor de tensión del módulo y finalmente a lux con la fórmula lux = (RL10 · 10³ · 10^γ / R)^(1/γ) (γ = 0.7, RL10 = 50 kΩ), tomada de la documentación del módulo.

¿Por qué 15 segundos en ThingSpeak? El plan gratuito de ThingSpeak permite una actualización cada 15 s; el backend espacía los envíos para no perder datos por límite de tasa.

11. Solución de problemas

Síntoma Causa probable Solución
ImportError: umqtt falta la biblioteca agrega micropython-umqtt.simple en el Library Manager
ImportError: ssd1306 falta la biblioteca agrega micropython-ssd1306; el sistema sigue sin OLED
El OLED queda en blanco dirección I2C incorrecta revisa i2cAddress: "0x3c" y los pines 21/22
[wifi] ERROR: sin respuesta SSID incorrecto usa Wokwi-GUEST (no pide contraseña)
[mqtt] ERROR al conectar sin Internet en Wokwi revisa que la simulación esté corriendo
No llega telemetría al backend mismo client_id en dos procesos usa IDs distintos (el CLI ya usa -cli)
SQLite … thread conexión usada desde otro hilo ya resuelto: check_same_thread=False + candado
ThingSpeak no recibe datos falta Write API Key exporta THINGSPEAK_WRITE_KEY
TalkBack no llega faltan credenciales o cola vacía exporta THINGSPEAK_TALKBACK_ID y _KEY, crea un comando
No se pudo encontrar el esquema ejecución fuera de la raíz corre python -m backend.main desde la raíz del repo
Alarma que no suena el buzzer necesita PWM AlarmPanel usa machine.PWM a 2 kHz; revisa mode: "smooth"
